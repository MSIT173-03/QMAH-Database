# ArtifactProductGenerator

從 QMAH 現有的 CC BY 4.0 文物建立課程示意商品。這些商品取代來源商城的商品圖片與即時價格。

工具預設為每件符合授權條件的文物建立一件商品。現有 8 類、每類 32 件、共 256 件，是目前參考 Snapshot 的資料量，不是產生器的固定上限；`--count all` 會依輸入資料包使用全部合格文物。

商品名稱固定為「文物名稱－縮小複製品」，不把「課程示意」放進名稱。商品圖片直接沿用 Catalog 路徑，不建立重複圖片。

## 商品說明模板

產生器依文物分類選擇商品開場，再帶入文物名稱與原始年代記錄。8 個分類各有 4 種開場，共 32 種模板：

| 分類 | 文案重點 |
| --- | --- |
| 玉器 | 玉色、玉工與溫潤質感 |
| 銅器 | 器形、紋飾與力量感 |
| 陶瓷 | 釉色、輪廓與桌面陳列 |
| 琺瑯器 | 鮮明色彩與華麗紋樣 |
| 漆器 | 漆藝、色澤與裝飾層次 |
| 雕刻 | 立體造形與多角度欣賞 |
| 錢幣 | 幣文、形制與歷史線索 |
| 繪畫 | 構圖、筆墨與畫面氣氛 |

同一個 `seed + ArtifactRef` 會固定選到同一個模板，重跑時文案不會變動。輸出 JSON 的 `copyTemplateId` 記錄實際使用的模板，例如 `jade-v1-2`，供追查與改版使用。

新增模板時應維持分類語氣，不宣稱商品真實存在、受歡迎、忠實還原材質或具有官方身分。

說明欄位依序包含：

1. 分類專屬的商品開場。
2. 非官方、沒有實際交易的用途聲明。
3. CC BY 4.0 圖像姓名標示。
4. 文物原說明全文。

開場控制在一個短段落，避免商品頁只剩制式聲明，也不讓宣傳文字蓋過原始文物資訊。文物原說明不截斷，前端可將「商品資訊」與「原文物說明」分區呈現。

## 尺寸換算

`--artifact-data` 讀取文物匯入 JSON 的 `artifactRef` 與 `sizeOriginal`。

套用時會同步更新 `catalog.Artifacts.SizeText`，再把所有以公分表示的線性尺寸除以 2，寫入對應商品的 `store.Products.SizeText`。Controller 與 View 直接顯示欄位，不再執行尺寸換算。

- 原作 `高35.6公分 口徑10.5公分` → 正規化為 `高 35.6 公分、口徑 10.5 公分`，商品為 `高 17.8 公分、口徑 5.25 公分`
- 原作 `148.7x73` → 正規化為 `148.7 × 73 公分`，商品為 `74.35 × 36.5 公分`
- 官方記錄為「待測量」→ 商品仍為「待測量」
- 官方未提供 → 商品仍為「官方資料未提供」
- 來源若把「通高／全高／高」的單位誤植為「公克」，工具只在這三種高度標籤後校正為「公分」；真正以「重」標示的重量不換算

商品尺寸已由工具換算為原作的一半，`SizeText` 只保存尺寸文字，不再附註比例。

尺寸只換算來源中明確出現的數值，不猜測缺漏資料。`--artifact-data` 若少了目前資料庫中的任何 ArtifactRef，工具會停止，不會產生對錯文物的商品。

價格範圍、商品數量與固定亂數種子都可調整：

```powershell
dotnet run --project .\ArtifactProductGenerator -- `
  --count all `
  --min-price 300 `
  --max-price 2200 `
  --seed 173 `
  --artifact-data D:\qmah-data\output\current\import\artifacts.json `
  --output D:\qmah-data\output\artifact-products.json
```

預設只產生 JSON 預覽。檢查名稱、文物、價格、說明、來源與姓名標示後，才使用畫面顯示的確認碼：

```powershell
dotnet run --project .\ArtifactProductGenerator -- `
  --count all `
  --min-price 300 `
  --max-price 2200 `
  --seed 173 `
  --artifact-data D:\qmah-data\output\current\import\artifacts.json `
  --output D:\qmah-data\output\artifact-products.json `
  --apply --approve <APPROVAL_TOKEN>
```

同一組參數與 seed 會選到相同文物並產生相同整數價格。

若資料庫已有購物車或訂單明細，工具會拒絕替換商品，避免破壞歷史資料。

若商品基準本身需要換名稱、說明、尺寸或價格，但資料庫已經有購物車與訂單，先輸出預覽並確認確認碼，再改用 `--refresh-existing --approve <APPROVAL_TOKEN>`。

這個模式只更新既有商品內容，保留商品 `Id`、購物車關聯與訂單明細中的成交快照。若目前商品的 `ExternalRef` 集合與預覽結果不同，工具會停止，避免把另一批商品誤當成同一批次。

`--count all` 會使用全部合格文物，使圖鑑與商城維持一對一。測試集可指定較小的整數；工具會在 8 類之間平均選取。

商品 `CategoryCode` 與文物分類代碼相同，`ArtifactId` 是直接連到文物的唯一外鍵。`ExternalRef` 仍固定為 `artifact-{ArtifactRef}`，只供資料交換與查重使用。

使用者前台若在圖鑑詳細頁加入「查看縮小複製品」按鈕，可直接用 `ArtifactId` 找到唯一商品，不必拆字串、比對名稱或重複圖片欄位。

## 售價規則

這裡的價格是課程商城測試資料，不是文物鑑價，也不代表官方複製品或市場售價。

```text
示意售價 = 280 元基礎價格
         + 年代久遠權重
         + 分類製作複雜度權重
         + 固定 seed 變化值
```

- 年代：以 `EraBuckets.StartYear` 與 `EndYear` 的中點估算距離參考年的年數，每 4 年加 1 元，四捨五入到十元，最高加 900 元。參考年由 `--reference-year` 指定，預設固定為 2026。
  缺少年代端點時也使用同一參考年，不受實際執行日期影響。
- 分類：玉器 500、琺瑯器 420、銅器 380、雕刻 340、漆器 300、陶瓷 260、繪畫 220、錢幣 100 元。這只表示假想複製製程的相對複雜度。
- 變化：依 `seed + ArtifactRef` 產生 0～240 元、每 10 元一級的固定變化，避免同年代同分類全部同價。
- 範圍：計算後四捨五入到十元，再限制在 `--min-price` 與 `--max-price` 之間。

輸出 JSON 的 `priceBreakdown` 會保存基礎價格、年代中點、距今年數、年代權重、分類權重、seed 變化、限制前與最終價格，便於檢查和調整。

## 與商城爬蟲的關係

`ArtifactProductGenerator` 是獨立的文物轉商品工具，也是目前正式資料流程。

原本的 `NpmShopSampleCollector` 不刪除，仍可研究商城分類、來源頁結構或在取得適當授權後重新評估商品素材。

它產出的商城圖片與價格不再直接匯入正式專題資料庫。兩套工具不互相覆寫設定。
