# 關聯式展示資料

此流程取代直接獨立生成文章、訂單、流水的做法。文案逐件依館藏資料撰寫，玩家、回答、投票與交易則按固定識別碼批量建立或修復。不需要登入多個帳號遊玩。

```powershell
./Invoke-ConnectedShowcase.ps1 -OutputSql C:/Temp/qmah-connected.sql
./Invoke-ConnectedShowcase.ps1 -Apply
```

此工具供維護者整理發布來源，不是組員的升級程序。組員應全新還原已驗證的完整 db-v0.12.0，不需再執行本工具。預設連線至 LocalDB 的 QMAH。第一行只匯出 SQL，第二行才更新資料。執行前先依現有發布流程備份目標資料庫。需要 db-v0.12.0 結構，預期 24 個既有展示帳號與 512 件啟用文物。

- 房間、回合、玩家、回答、回合投票依共同來源生成，24 個帳號各有 64 筆玩家紀錄。回答類型輪替，不建立會員性格模型。
- 每位會員補上四種單人玩法的完成紀錄，共 96 筆。素材池、結果 JSON、等級與獎勵流水保持同一來源，歷史日期不影響今天的點數額度。一般拼圖採 25 片、長卷採 15 片，結果中的耗時與開始時間一致。重跑僅修復固定種子識別碼的結果，不重發獎勵，也不修改玩家尚未完成的遊戲。
- 依每位會員已有的 64 個不同文物回合補齊圖鑑解鎖，保留原有收藏後每人 64～69 件，涵蓋八個分類。每筆新增解鎖都連到本人參與的已完成回合，不另發鑰匙。同步補上已達門檻的收藏與年代完成成就，不變更已裝備稱號。
- 鑑賞票是獨立的會員投票，不能投自己的回答，也不與回合內計分票混用。
- 遊戲種子房間保留內部來源欄位，不能領正式獎勵或取得每日突破資格。玩家介面不顯示展示標籤。
- 訂單從根紀錄分配，付款與明細保持同一訂單。評論必須能找到該會員已付款的購買紀錄。歷史價格快照不按現在售價重算。
- 暱稱改為文物相關名稱，全域管理員為「鑑定屋館長」。登入 email、密碼、安全戳記與角色在交易前後比對，不符即回復。
- 只處理可確認為種子來源的資料，不憑 UserId 或看起來像假資料就重寫其他紀錄。中性館藏、商品與定義表不強行分配會員。
- 固定鍵與存在檢查避免重跑增加相同資料。整批共用一個交易，關聯驗證失敗即回復，不停用或放寬資料庫約束。
- 舊種子超過 100 的鑰匙進度依既有設定兌換成一般鑰匙，補上同一來源的兩筆流水，保留不足門檻的餘數。

`answers.json` 是正式種子輸入資料。圖片、帳密、外部測試結果與文案產生工具不納入此目錄。

審核情境保留原手動測試紀錄，新增 24 篇貼文與 24 筆檢舉，分為 12 筆隱藏、8 筆待審與 4 筆駁回。只在固定識別碼不存在時新增，不覆蓋後續人工審核。舊累積進度與單局兌換分開，實得鑰匙逐筆對應單局收據，重跑不增加持有量。
