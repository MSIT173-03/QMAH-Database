# QmahTestDataWorkbench

Windows WPF 測試資料工作台，位於 QMAH-Database，提供：

- 自動尋找本機含有 `QMAH` 資料庫的 SQL Server instance。
- 讀取文物與商品清單，受控新增或編輯這兩類資料。
- 建立或更新展示會員。
- 以既有 `QmahDatabaseRelease` 產生一批可追查的社群、商城、付款、每日活動與資產流水資料。
- 依資料庫目前啟用的成就條件補上符合門檻的登入成就。
- 顯示執行記錄與資料庫目前筆數。

這個工作台不執行網站啟動、不建立 Schema、不套用 Migration，也不提供任意資料表的無限制 CRUD。訂單、付款、訂單明細、評論與其他跨表資料由既有產生器一次處理，避免只建立其中一張表而留下無效外鍵或不一致狀態。

## 建置與啟動

從 QMAH-Database 根目錄執行：

```powershell
dotnet restore .\QMAH.DatabaseTools.sln
dotnet build .\QMAH.DatabaseTools.sln -c Release
dotnet run --project .\tools\QmahDataTools\QmahTestDataWorkbench\QmahTestDataWorkbench.csproj
```

第一次啟動會先以現有連線字串為提示，接著搜尋本機候選 SQL Server instance。搜尋只確認 `sys.databases` 是否存在在線上的 `QMAH`，不會掃描網路、自動附加 `.mdf` 或自動還原 `.bak`。若有指定連線設定，該設定會優先於自動搜尋結果。

## 一鍵建立關聯展示資料

1. 從「展示帳密檔」按「範本／填寫帳密」。沒有本機檔時，工作台會由版本庫的 `QMAH.DemoCredentials.csv` 建立未提交的 `QMAH.DemoCredentials.local.csv`。
2. 在工作台內為所有展示會員填入測試密碼並儲存；同時會更新本機備份檔。
3. 確認資料庫已有可用文物與對應商品。商品可由「商品資料」頁新增，或使用 `ArtifactProductGenerator`。
4. 設定貼文數、訂單數、每日活動天數、點數／鑰匙／鑰匙進度流水筆數與固定 seed。
5. 按「一鍵建立完整展示資料」。

預設本機帳密檔與備份檔放在偵測到的 Repository 資料夾上一層，不依賴工作區名稱。兩個 Repository 位於同一個父資料夾時，可以共用這兩個本機檔案。版本庫內的 `QMAH.DemoCredentials.csv` 只提供顯示名稱、Email 與角色範本，不放密碼。

工作台可以改用「選擇檔案」指定其他 CSV；密碼欄位使用遮罩輸入，儲存時會同時更新本機備份。任何未填密碼的列仍會由 `seed-showcase-users` 拒絕執行。

按鈕會依序執行：

```text
seed-showcase-users
generate-showcase-data
```

第二個命令會以穩定識別碼重跑相同批次，並在單一交易中處理社群貼文、留言、商城訂單、訂單明細、付款、商品評價、每日登入／簽到、點數流水、鑰匙流水、鑰匙進度流水與符合登入條件的成就。批次失敗時會回滾這一批 Entity Framework 變更；展示會員的建立／更新則是另一個交易。

只需要補產生資產與登入情境時，可以單獨執行 `generate-showcase-ledger`。該命令不會產生貼文、訂單或商品，只處理活動與四種資產／成就資料。

## 流水與成就的產生規則

下列資料不是把固定 SQL 或固定成就編號寫死在工作台：

| 資料 | 來源與規則 |
| --- | --- |
| 每日活動 | 依目前啟用展示會員與 `--activity-days` 建立 `LOGIN`；部分日期另建 `CHECK_IN`，日期只到執行日前一天 |
| 點數流水 | 以固定 seed 產生可重跑的取得／使用紀錄，標記 `ReferenceType=SHOWCASE_GENERATED`，餘額先扣除舊的工具流水再重算 |
| 鑰匙流水 | 讀取資料庫中啟用的 `catalog.KeyDefinitions` 後分配到展示會員；沒有啟用定義時只輸出警告並略過 |
| 鑰匙進度流水 | 依展示會員產生可重跑的累積／使用紀錄，與一般鑰匙流水分開維護 |
| 登入成就 | 讀取啟用中的 `DAILY_LOGIN_COUNT`／`DAILY_LOGIN_STREAK` 定義與門檻，只有實際登入歷史達標才建立 `UserAchievements` |

`seed-showcase-users` 另有少量固定的成就展示分配，用來讓成就清單在沒有登入歷史時仍有可查看資料；那是展示帳號的初始 fixture，不是產品成就判定規則。`generate-showcase-data` 與 `generate-showcase-ledger` 的登入成就則依資料庫條件與登入歷史計算。所有工具流水都使用穩定識別碼，重跑時只更新 `SHOWCASE_GENERATED` 的資料，不刪除其他來源的歷史列。

## 文物與商品編輯

工作台只提供兩個有明確資料規則的編輯範圍：

- 文物：必填文物編號、名稱、分類、年代分類、主圖片路徑與來源網址；分類與年代從資料庫既有清單選取。
- 商品：必填名稱、商品分類代碼、價格與庫存；可選擇已存在的關聯文物。

儲存文物或商品不會自動產生題庫、商品、訂單或付款資料。需要完整關聯時，應先完成文物與商品資料，再執行「一鍵建立完整展示資料」。

## 可調整的展示資料參數

「快速產生」頁的欄位分別控制：

| 欄位 | 範圍 | 作用 |
| --- | ---: | --- |
| 社群貼文數 | 1–512 | 產生或更新工具管理的社群貼文批次 |
| 商城訂單數 | 1–512 | 產生或更新訂單、訂單明細、付款與商品評價批次 |
| 每日活動天數 | 0–3650 | 每位展示會員往前建立的登入／簽到日期範圍；不含今天 |
| 點數流水筆數 | 0–10000 | 工具管理的點數取得／使用紀錄總數 |
| 鑰匙流水筆數 | 0–10000 | 工具管理的一般鑰匙取得／使用紀錄總數 |
| 鑰匙進度流水筆數 | 0–10000 | 工具管理的鑰匙進度取得／使用紀錄總數 |
| 固定 seed | 0 以上 | 決定同一批展示資料使用的固定選擇順序 |

相同的數量與 seed 會重用穩定識別碼，適合重跑與檢查；調整數量會擴充或更新對應批次。活動天數縮短時，既有活動歷史不會被刪除；三種資產流水只會清理同一個 `SHOWCASE_GENERATED` 批次中已不再需要的列。工作台不會因為執行這些命令刪除非工具產生的資料，也不會建立 Schema、執行 Migration 或啟動網站。

文物與商品的「資料」頁提供受控單筆編輯：文物必須填入 `ArtifactRef`、名稱、分類、年代分類、主圖片路徑與來源網址；商品必須填入名稱、商品分類代碼、價格與庫存，並可選擇關聯文物。跨表的題庫、訂單、付款與評論資料不在單筆編輯器中直接拼接，改由已驗證的產生器處理。

## 與其他工具的界線

`NpmDataWorkbench` 是另一個 WPF 工作台，負責遠端 NPM 文物資料與商城來源的收集、預檢及匯入；本工作台負責已還原資料庫內的測試資料維護與關聯批次。兩者不合併，避免資料來源處理與資料庫狀態編輯互相干擾。

完整命令、Snapshot、Schema 比對與 `.bak` Release 交付規則見 [QMAH-Docs 資料工具參考](https://msit173-03.github.io/QMAH-Docs/reference/data-tools.html)。
